# Quota alerts

- **Status**: DONE
- **Slug**: quota-alerts
- **Created**: 2026-06-02
- **Plan**: plan/ · **Verified**: verification/01-report.md

## Intent

A workspace owner is told before a quota runs out, not after the API starts
refusing writes. Observably true when this ships: crossing 80% of a metering
window's quota delivers one notification per threshold per window.

## Decisions

- 2026-06-03 — **Thresholds are evaluated on the closed metering window, not
  on live counters.** Because the live counter is eventually consistent across
  regions and would fire duplicate alerts. Evidence:
  `research/usage-metering-windows/` chapter 02.

## Capabilities

- Evaluate 80% and 100% thresholds when a metering window closes.
- Deliver one notification per threshold per window over the existing channel.
- Show a quota banner on the workspace header while a threshold is crossed.

## Must not

- MUST NOT introduce a second notification transport — the existing channel
  already carries delivery receipts.

## Research

- [`research/usage-metering-windows/`](../../research/usage-metering-windows/README.md)
  — window closure semantics and the duplicate-alert failure mode.
