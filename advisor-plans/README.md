# Advisor Plans — Native `/goal`, Deterministic Acceptance

Generated by the `improve` skill on 2026-08-09 and reverified on 2026-08-10 at
commit `04987c8`. See [RESEARCH.md](RESEARCH.md) for the upstream comparison,
local defect-class audit, provider checks, and trust limits.
This repository reserves `plans/` for Tailrocks delivery packages, so advisor
handoffs live under `advisor-plans/`.

The target is not deterministic model output. The target is deterministic
acceptance against a frozen intent contract, while preserving the user's chosen
execution surface:

> Agents propose. Verifiers prove. Only current evidence changes canonical
> state.

The user starts native `/goal`: Codex first, Grok second, Claude Code third.
`tailrocks goal ...` is the trusted control/check layer used by generated
`GOAL.md` and provider hooks. It does not replace `/goal`, choose another model
loop, or require a separate supervisor workflow.

Execute in order unless dependency notes permit parallel work. Every executor
must read its plan fully, run all gates, honor STOP conditions, commit with DCO
signoff plus `Co-authored-by: Codex <codex@openai.com>`, and never push or open a
PR without operator instruction.

Run shell commands through `rtk` by default (`rtk <command>` or `rtk proxy
<command>` when passthrough is required), following the repository's `RTK.md`.
Command tables name the underlying command/arguments. Priorities express
correctness dependencies, not cost/effort/ROI; every listed plan is required for
the promised end state.

  regression evidence. It also fixes fixture staging before new delivery cases
  are added.
- 002 supplies typed IDs, schemas, hashing, and a deterministic validator.
  Plans 003–005 extend that control plane instead of reimplementing validation
  in skill prose.
- 003 freezes source provenance and READY intent before 004 compiles executable

- 004 defines coverage, scope/effect budgets, protected oracles, exact version
  resolution, and generated handoff artifacts. 005 then gives those contracts

- 006 and 007 separate execution from certification without replacing the

  `tailrocks goal` selects one eligible slice, persists budgets, verifies a

- 010 is the integration/release gate. It migrates examples, runs cross-client

## End-state invariants

- Every normative intent statement has an immutable source anchor and stable
  requirement ID.
- Every requirement has an acceptance gate or an explicit semantic, human, or
  external verifier. Every gate maps back to requirements.
- Every plan declares authorized effects; every resulting diff/effect maps to a
  plan or a declared technical prerequisite.
- Acceptance oracles cannot change during execution without invalidating the
  package.
- Native `/goal` is the only primary execution UX. Provider hooks and the thin
  generated prompt delegate eligibility, scope, budgets, verification, and
  terminal classification to `tailrocks goal`; native model confidence never
  defines completion.
- Executors may submit a candidate; they cannot write `DONE`.
- `DONE` is computed from passing receipts tied to current contract, plan,
  oracle, resolution, environment, and repository subject-tree hashes. A
  separate control-generation hash lets status/retirement commits preserve a
  still-current implementation receipt.
- Reconcile inspects repository reality through independent Product Contract,
  Scope, and Engineering Integrity axes. Model claims never override a failed
  deterministic check.
- A verified package leaves a durable spec and attestation, then removes its
  active `plans/<slug>/` directory.
- Every workflow transition and backtrack has one state-derived route. A model
  may explain it but cannot choose a different authoritative stage.
- Every nominal completion is replayed in a second clean verifier worktree and
  followed by deterministic final reconciliation before a current `PASS`
  receipt may exist.

## Considered and rejected

- Promise exact patch determinism from an LLM: rejected. Exact source output
  requires a deterministic generator, codemod, compiler, or template.
- Add more interview/reviewer prose without enforcement: rejected. Existing
  macro-lifecycle is sound; missing boundary is executable validation outside
  the model.
- Treat `/goal` model evaluation as proof: rejected. It remains a persistence
  mechanism and execution UX; only the Tailrocks verifier certifies acceptance.
- Replace native `/goal` with a standalone provider supervisor: rejected. The
  controller is deliberately subordinate to Codex/Grok/Claude `/goal`; it
  supplies state, hooks, clean-room checks, and receipts rather than owning the
  conversation loop.
- Let `REJECTED` satisfy package completion: rejected. Required work can leave
  the package only through an explicit contract change that restores coverage.
- Store canonical machine state in hand-edited Markdown tables: rejected.
  Machine artifacts are canonical; Markdown status views are generated.
- Delete completed packages without preserving spec/evidence: rejected. Active
  plans are disposable; finalized contract and attestation are durable.

## Proof boundary

Deterministic acceptance is relative to contract completeness, oracle quality,
current evidence, and verifier trust. Semantic/visual intent stays explicitly
semantic or human-owned. Local evidence is not called adversary-resistant when
the same unrestricted host can alter both executor and verifier.
