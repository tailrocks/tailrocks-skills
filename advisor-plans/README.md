# Tailrocks Naming and Model-Routing Improvement Plans

Generated by the `improve` skill on 2026-08-20 from commit `13a5ee5`.
These are planning artifacts only. They intentionally do not implement the
recommended source changes.

Execute in order unless a dependency says otherwise. Each executor must read
its whole plan, run the drift check first, honor every STOP condition, and
update its row here when done.

## Settled architecture

Two invariants drive all five plans:

1. Every user-visible Tailrocks skill surface begins with `Tailrocks`; stable
   skill IDs remain `tailrocks-*`.
2. Model routing follows capability and evidence, not provider loyalty or
   price. A lower-cost model receives work only after the work is bounded by a
   self-contained plan and representative evals prove that route. Ambiguity,
   architecture, security, escalation, and final semantic acceptance stay on a
   frontier-judgment route.

The shared skill tree remains provider-neutral. Model names and client syntax
belong in a versioned client capability registry and generated/user-facing
documentation, never in `SKILL.md` bodies.

## Capability roles

| Role | Owns | Must not own |
|---|---|---|
| `human-decision` | Product intent, irreversible authorization, unresolved preference | Delegable implementation work |
| `frontier-judgment` | Ambiguous architecture, decomposition, risk classification, escalation, final semantic review | Repetitive search or mechanical edits when a narrower role is proven |
| `bounded-executor` | One self-contained plan with exact scope, commands, done criteria, and STOP conditions | New product decisions, scope expansion, silent recovery from drift |
| `fast-mechanical` | Search, indexing, extraction, formatting, deterministic transforms | Semantic acceptance or architecture |
| `independent-verifier` | Fresh-context adversarial verification against stated evidence | Editing the work it judges |
| `deterministic-gate` | Commands and schemas whose exit status decides a mechanical claim | Subjective quality judgments |

Claude Fable 5 is the preferred current Claude route for
`frontier-judgment`, especially multi-stage planning and orchestration. It is
not the universal executor. Claude Sonnet handles bounded implementation and
Haiku handles narrow mechanical work after eval proof. Equivalent current
routes are GPT-5.6 Sol/Terra/Luna in Codex. Other clients map capabilities,
not model brand names; clients without verified mixed-model delegation use
the same checked-in plan artifact across separate sessions.

## Current research basis

Re-verify these sources and installed client versions when implementing; model
and CLI facts are intentionally treated as release-dated data.

- Anthropic documents Fable 5 as its most capable generally available model
  for ambitious, long-running work, including planning, delegation, and
  self-checking: <https://www.anthropic.com/claude/fable>.
- Claude Code supports model selection per subagent and explicitly recommends
  faster models for simple subagent work:
  <https://code.claude.com/docs/en/sub-agents>.
- OpenAI maps GPT-5.6 Sol to frontier work, Terra to balanced work, and Luna to
  high-volume work: <https://developers.openai.com/api/docs/guides/latest-model>.
- Codex exposes configurable subagent models and reasoning:
  <https://learn.chatgpt.com/docs/agent-configuration/subagents>.
- OpenCode agents support per-agent provider/model selection:
  <https://opencode.ai/docs/agents>.
- Kimi subagents support a documented optional per-invocation model override;
  no separate primary/secondary tier contract is established by that page:
  <https://moonshotai.github.io/kimi-cli/en/customization/agents.html>.
- Antigravity custom subagents select `inherit`, `flash`, or `pro` tiers:
  <https://antigravity.google/docs/subagents>.
- Amp modes currently combine Fable, Sol, Terra, and smaller models, but the
  mappings are managed and may change: <https://ampcode.com/modes>.
- Grok Build supports selecting a top-level custom model, while current public
  documentation does not establish a per-subagent heterogeneous-model
  contract: <https://docs.x.ai/build/overview>.

## Findings considered and rejected

- Rename skill directories or `SKILL.md` names: rejected. All 37 shipped IDs
  already use `tailrocks-*`; changing them would break stable invocation paths
  without fixing the Codex display-label defect.
- Duplicate one skill per client or model: rejected. It violates the shared
  source tree and creates behavior drift.
- Put Fable, GPT, Gemini, or client command syntax in shared skill bodies:
  rejected. Provider mappings are volatile and the repository requires
  source-neutral `SKILL.md` bodies.
- Always choose the cheapest model: rejected. A route is eligible only when
  task boundaries and representative evals prove it preserves the contract.
- Pretend every client supports same-session mixed-model delegation: rejected.
  Use a cross-session artifact handoff where the capability is unverified.
- Run credentialed seven-client live evals in deterministic PR CI: rejected.
  Static schemas and fake-adapter tests belong in CI; live compatibility runs
  belong in dated release evidence.
- Treat inline self-review as independent review when no subagent exists:
  rejected. It removes the very independence the gate claims.

## Audit findings not promoted into separate plans

- The example goal package uses `true` as its only gate while its prompt claims
  `mise run test` and `mise run lint` define completion. Plan 002 includes the
  fix because the example is part of the execution-handoff contract.
- The eval judge receives subject artifacts without an explicit untrusted-data
  boundary. Plan 004 includes the guard and adversarial regression test.
- Generated skill documentation titles are unbranded. Plan 001 includes them
  because they are a primary user-visible skill surface.
