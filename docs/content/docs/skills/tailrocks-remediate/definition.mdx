Execute one exact correction already diagnosed by `tailrocks-root-cause` and
explicitly approved by the user. This owner does not prove wrongness, derive a
design, expand the defect class, or treat a diagnosis report as mutation
authority.

Only explicit `fix` plus the exact current approved contract continues. Reject
omitted, `analyze`, `rebuild`, mixed, or unknown selectors unchanged; this owner
is not a compatibility router.

Apply [`runtime-trust.md`](https://github.com/tailrocks/tailrocks-skills/blob/main/skills/tailrocks-remediate/references/runtime-trust.md).

## Apply the correction

1. Bind canonical repository, current HEAD, merge base/range, dirty-state digest,
   diagnosis ID and hashes, approval text, exact allowed paths and breaks,
   expected preimages, prevention claim, migration slices, expiry, and every
   irreversible or external step. Reject stale, ambiguous, symlinked, escaping,
   broadened, or self-approved contracts. Re-diagnosis, redesign, or approval
   change routes back to `tailrocks-root-cause` and the user.
2. Revalidate the reported contradiction, causal boundary, affected consumers,
   persisted/wire forms, compatibility promises, and capability set. A mismatch
   blocks; never repair the contract in place. Preserve all behavior not named in
   the approved break inventory.
3. Require green pre-edit regression evidence for the reported instance and a
   boundary/property oracle for the defect class. Add an approved characterization
   test before production mutation when needed and prove it against unchanged
   production bytes. A red, vacuous, unavailable, or mutation-prone baseline
   blocks application.
4. Run commands only with explicit execution authority, frozen dependencies and
   inputs, scrubbed secrets, disabled network unless the approved operation needs
   one exact endpoint, owner-only external cache/output, bounded
   time/retries/output/process tree, TERM-then-KILL cleanup, and repository hashes
   before/after every proof run.
5. Execute one approved never-broken slice at a time. Publish every changed path
   sequentially by expected-preimage-to-owned-postimage CAS with a per-path
   receipt; never claim multi-path atomicity. Check the slice invariant and
   focused oracle before continuing. Temporary bridges must carry their approved
   removal condition and cannot be reported as the destination.
6. Before each destructive, irreversible, persisted-data, published-contract, or
   outward action, require fresh action-specific user approval bound to exact
   target and current state. A data migration must be resumable and idempotent,
   verify backup and checksum, follow expand-migrate-contract, and name the
   forward-recovery path; never promise rollback of an irreversible effect. If
   active harm requires approved containment, apply only the named reversible
   measure and report `CONTAINED`, never `CORRECTED`, until cause removal.
7. On failure, restore a preimage only by CAS after current bytes prove they still
   match this invocation's owned postimage. Preserve concurrent replacements.
   If any mutation survives, stop and name every changed path, partial migration,
   and recovery artifact as `RECOVERY_REQUIRED`.
8. Run focused and full repository gates under the same bounded contract. Prove
   the reported instance, the approved bounded class, every migration invariant,
   final break inventory, exact changed-path allowlist, structural measure, and
   removal of every temporary bridge due in this slice.

## Output and final gate

Return exactly one of `CORRECTED`, `CONTAINED`, `BLOCKED`, `REFUSED`, or
`RECOVERY_REQUIRED`, bound to repository/HEAD and diagnosis/approval identity,
with pre/post hashes, per-path CAS receipts, commands and units, instance and
class-prevention evidence, approved breaks, residual exposure, partial mutations,
and recovery artifacts. `CORRECTED` requires the full approved cause removal;
`RECOVERY_REQUIRED` means at least one mutation survives. No unapproved edit,
behavior change, scope expansion, commit, push, merge, issue, comment, dependency
install, credential use, network call, or external action.
