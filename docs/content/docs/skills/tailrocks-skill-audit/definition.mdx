The audit applies the authoring doctrine this skill carries — the design,
testing, and house-wiring doctrine in its references — to one skill or a
whole tree and produces the defect report. The report is the product: it
is the evidence a fix is applied from, and
[`report-format.md`](https://github.com/tailrocks/tailrocks-skills/blob/main/skills/tailrocks-skill-audit/references/report-format.md) makes it consumable by
`tailrocks-skill-refactor` one finding ID at a time.

Read-only on everything audited. The single write is the report file
under `skill-audits/`; never edit a skill, an eval, or a wire — a defect
present does not imply permission to remove it.

## Modes

- `<skill name>`: audit one skill.
- `all`: sweep every skill in the tree. Fan the reads out — one read-only
  investigator subagent per skill, fresh context each, carrying the
  doctrine pointers, the report format, and the hard rules verbatim —
  then vet in your own context. Investigators never hold the whole tree.

## Steps

1. **Inventory.** Locate the skill: `SKILL.md`, `references/`,
   `templates/`, client metadata, `evals/evals.json` and its fixtures,
   plus the tree's wiring surface (catalog, generated docs, install and
   index documents, version pins). In `all` mode, enumerate the tree's
   skill directories first; every one gets an investigator.
   **Complete when:** every in-scope skill has its full file surface
   named.

2. **Judge against the doctrine.** Read
   [`design-doctrine.md`](https://github.com/tailrocks/tailrocks-skills/blob/main/skills/tailrocks-skill-audit/references/design-doctrine.md) for description,
   router, and reference defects;
   [`testing-doctrine.md`](https://github.com/tailrocks/tailrocks-skills/blob/main/skills/tailrocks-skill-audit/references/testing-doctrine.md) for eval
   defects; [`house-wiring.md`](https://github.com/tailrocks/tailrocks-skills/blob/main/skills/tailrocks-skill-audit/references/house-wiring.md) for wiring
   gaps. Judge overlap last: two skills owning one responsibility is a
   defect even when both are internally clean. Judge against the working
   repository's own skill-tree conventions first when it carries them (a
   `skills/AGENTS.md`, a validator, an eval runner); this doctrine fills
   what those do not cover.
   **Complete when:** each layer of each skill is judged or explicitly
   clean.

3. **Vet against your own reads.** Re-open every cited line yourself.
   Kill by-design behavior, mis-attributed evidence, and duplicates with
   a one-line recorded reason. An investigator's finding you did not
   re-read is not a finding.
   **Complete when:** every surviving finding carries evidence you
   opened, and every killed one carries its reason.

4. **Write the report.** One report file per skill under `skill-audits/`
   at the audited repository's root, per
   [`report-format.md`](https://github.com/tailrocks/tailrocks-skills/blob/main/skills/tailrocks-skill-audit/references/report-format.md): findings by layer
   with stable IDs and named fixes, clean layers stated, killed findings
   listed with reasons. A re-audit overwrites the same file. In
   conversation, present the per-skill verdict lines and counts — the
   file carries the detail.
   **Complete when:** the report file is written and every finding in it
   has an ID and a fix.

## Boundaries

Audits skill authoring only. Repository code defects route to
`tailrocks-improve` (pipeline-free repositories) or `tailrocks-audit`
(repositories running the delivery pipeline). Applying report findings
is `tailrocks-skill-refactor`, by ID, after the user selects.
Authoring a new skill is `tailrocks-skill-create`; an in-place edit is
`tailrocks-skill-update`. For any of those, name the route and stop.

## Red flags — STOP

- "Fix it while you're in there" — the audit never edits; application
  is the refactor skill's job, on user-selected IDs.
- A finding reported without re-opening its evidence — evidence or
  silence.
- One agent sweeping the whole tree alone — investigators per skill,
  fresh contexts, verdicts in the main context.
- A finding with no ID or no named fix — a report that cannot be
  consumed is trivia.
- Treating a clean-by-design choice as a defect — the kill list exists
  to record exactly these.

## Final gate

Never edit during an audit. Never report a finding whose evidence you
did not open. Never skip the report file or write it anywhere but
`skill-audits/`. Never quote a secret value — cite location and type.
Never let investigator output reach a report unverified. Never audit
against doctrine the repository's own conventions already settle
differently. Report every check skipped.
