## 1. Overview and Dictionary Architecture

The ASD-STE100 dictionary is a **controlled technical vocabulary** designed to eliminate semantic ambiguity, prevent grammatical misunderstandings, and maximize readability for technical operators and non-native English speakers.

Unlike general-purpose English dictionaries, ASD-STE100 enforces two strict linguistic baselines:
1. **One Word, One Meaning (Rule 1.3)**: Every approved word possesses exactly one core technical sense (or clearly demarcated numbered sub-senses). Metaphorical, colloquial, or secondary meanings are prohibited.
2. **One Word, One Part of Speech (Rule 1.2)**: Functional shift (conversion) is forbidden. Words approved as nouns cannot serve as verbs (`check (v)` and `test (v)` are strictly non-STE), and adjectives cannot serve as verbs.

This bundled lexical repository provides direct access to 1,956
dictionary entries across 20 alphabetical shards and 2 specialized
reference matrices, without requiring external PDF files, page
coordinate calculations, or third-party extraction tools. Entry
counts below match the actual shard files. The authorized Issue 9
copy stays authoritative for words outside the bundled coverage.

## 4. Five-Step Agent Consultation Protocol

When evaluating candidate text, revising non-compliant documents, or verifying vocabulary, AI agents must execute this deterministic 5-step lookup procedure:

```
[ Step 1: Identify Word & POS in Context ]
                      │
                      ▼
[ Step 2: Open Applicable Alphabetical Shard ]
                      │
                      ├──► Found in UPPERCASE? ──► Approved Word (Proceed to Step 3)
                      │
                      ├──► Found in lowercase? ──► Unapproved Word (Proceed to Step 4)
                      │
                      └──► Not in Dictionary?  ──► Check TN / TV Criteria (Rule 1.5 / 1.12)
                      │
                      ▼
[ Step 3: Verify Sense, Forms & Help Notes ]
                      │
                      ├──► Sense matches Column 2 definition?
                      ├──► Tense/form matches Column 1 listed forms?
                      └──► Complies with Category 1-4 Help notes?
                      │
                      ▼
[ Step 4: Resolve Unapproved Guide Words ]
                      │
                      ├──► Select suitable Column 2 approved alternative
                      └──► Choose direct word-for-word replacement or sentence reconstruction
                      │
                      ▼
[ Step 5: Verify Semantic Fidelity & Flow ]
                      │
                      └──► Confirm technical accuracy, safety, and readability preserved
```

### Detailed Protocol Steps

1. **Step 1: Identify Word and Part of Speech in Context**:
   - Determine how the word functions grammatically in the target sentence (noun, verb, adjective, adverb, preposition, conjunction).
   - *Example*: In *"Check the pressure"*, `check` is intended as a verb.

2. **Step 2: Locate the Headword in the Alphabetical Shard**:
   - Navigate to the appropriate shard (e.g., [`c.md`](c.md) for `check`).
   - If the word is absent from the shard, consult the authorized
     Issue 9 copy per [`source-access.md`](../source-access.md)
     before a Strict verdict. Absence from a bundled shard is not
     proof of unapproved status.
   - Check the headword formatting:
     - **UPPERCASE BOLD** = **Approved word**. You may use this word, provided you obey its specified POS and approved meaning.
     - **lowercase bold** = **Unapproved word**. You are strictly prohibited from using this word unless it qualifies as a recognized Technical Noun (TN) or Technical Verb (TV).

3. **Step 3: Inspect Approved Meaning, Inflections, and Help Notes**:
   - If approved:
     - Read the **Approved Meaning** in Column 2. Does your intended meaning match this exact definition? If not, you *cannot* use the word.
     - Check **Forms / Inflections** in Column 1. Regular verbs require `-ed`. Irregular verbs list all valid forms. If a form is missing (or marked *No other verb forms*), it cannot be used.
     - Inspect **Help Notes**:
       - *Category 1*: Usage instructions (e.g., required prepositions).
       - *Category 2*: Restricted meaning. Mandatory alternatives must be used for other meanings (for example, `ABOUT (prep)` means *concerned with*). Use `APPROXIMATELY` or `AROUND` for other senses.
       - *Category 3*: Context-specific restriction (e.g., `SWALLOW (v)` for safety instructions only).
       - *Category 4*: Special grammatical notices (e.g., omission advice, defective forms).

4. **Step 4: Resolve Unapproved Guide Words**:
   - If unapproved:
     - Read the **Approved Alternatives** in Column 2.
     - If the alternative has the same POS, perform a direct **word-for-word replacement** (e.g., `acceptable (adj)` -> `PERMITTED (adj)`).
     - If the alternative has a different POS, perform a **sentence reconstruction** (e.g., `check (v)` -> `DO A CHECK (n) OF...` or `MAKE SURE (v) THAT...`).
     - Check whether the unapproved word qualifies as an authorized **Technical Noun (TN)** under Rule 1.5 or an authorized **Technical Verb (TV)** under Rule 1.12.

5. **Step 5: Semantic Fidelity and Quality Verification**:
   - Verify that the rewritten sentence preserves 100% of technical tolerances, causal relationships, safety implications, and procedural sequences.
   - Confirm that the sentence obeys ASD-STE100 sentence length
     limits (Rule 5.1: max 20 words for procedural instructions,
     and Rule 6.3: max 25 words for descriptive statements).

## 5. Critical Lexical Pitfalls for Automated Systems

Automated language models frequently make the following five critical errors when writing Simplified Technical English. Agents must actively check against these traps:

1. **`CHECK` is NEVER a verb**:
   - `CHECK (n)` is an approved noun meaning *"The procedure you do to make sure that something operates correctly or has no defects"*.
   - `check (v)` is **unapproved**. Use `MAKE SURE THAT...`, `EXAMINE`, `MEASURE`, or the noun phrase `DO A CHECK OF...`.
   - *Reference*: [`c.md#check-n`](c.md#check-n), [`c.md#check-v`](c.md#check-v).

2. **`TEST` is NEVER an ordinary action verb**:
   - `TEST (n)` is an approved noun.
   - `test (v)` is **unapproved**. Use `DO A TEST OF...` or `DO A FUNCTIONAL TEST OF...`.
   - *Reference*: [`t.md#test-n`](t.md#test-n), [`recurring-errors.md#335-test-v---test-n-do-v`](recurring-errors.md#335-test-v---test-n-do-v).

3. **`CAREFULLY (adv)` is fully APPROVED**:
   - `CAREFULLY (adv)` is an approved core adverb meaning *"In a careful manner"*.
   - Models frequently hallucinate that `CAREFULLY` is unapproved. It is explicitly approved on physical page 185.
   - *Reference*: [`c.md#carefully-adv`](c.md#carefully-adv).

4. **`CAN (v)` vs `COULD`**:
   - `CAN (v)` is approved as an auxiliary modal verb meaning *"to be possible, to be able to, or to be permitted to"*.
   - `could` is **strictly prohibited for possibility** (Help Category 1/4). Always write `CAN OCCUR`, never `could occur`.
   - *Reference*: [`c.md#can-v`](c.md#can-v).

5. **`ABOUT (prep)` has a RESTRICTED meaning**:
   - `ABOUT (prep)` is approved **only** to mean *"Concerned with"* (`DATA ABOUT THE SYSTEM`).
   - For numerical estimates, you must use **`APPROXIMATELY (adv)`**.
   - For circular spatial rotation, you must use **`AROUND (prep)`**.
   - *Reference*: [`a.md#about-prep`](a.md#about-prep).
