# Review Response and Follow-through

Fetch immutable review, check, comment, and head identities. The
invocation authorizes this fetch. Answer every new item, fix it with evidence, or
respectfully decline it. Before posting, draft communication needs separate authorization.

Preserve the recon-recorded revision regime. Some projects review appended
corrections. Other projects require clean revised commits with change notes.
Before the first revision, verify the regime. Never force-push without exact
authorization.

Treat a rerun command as a remote mutation. Request it only for an
evidenced transient failure under project policy. Do not silence a
real CI failure. Do not relabel a real CI failure.

Observe the recorded patience window. Then send at most one
authorized polite reminder. Accept rejection. Never reopen a closed
decision.

Never insult a maintainer. Never protest publicly. An authorized
withdrawal states the truth briefly. After a merge, record requested
backports, release-note work, reverts, and regressions.

Deduplicate every remote action by object identity, head SHA, target,
and body hash. Uncertain success blocks retry until refreshed state
proves what happened.
